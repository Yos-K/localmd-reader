# ADR-0022: 直接受信したMarkdownタブを復元可能にする

状態: 採用

## 決定事項

Termuxなどから本文を直接受信して開いたMarkdownも、通常の保存済みファイルと同様に
Back後およびプロセス再起動後に復元する。受信本文はアプリ専用の内部ストレージへ保存し、
入力元の識別子をSHA-256でハッシュ化したディレクトリへ格納する。同じ入力元を再受信した
場合は、タブを重複させず、保存本文を最新内容へ置き換える。

## 検討した選択肢

- 直接受信したタブは現在のプロセスでだけ保持する。
- 本文をタブ設定とともにSharedPreferencesへ保存する。
- 受信本文をアプリ内部ファイルへ保存し、既存のファイル復元経路を利用する。
- 利用者に明示的な保存を要求する。

## 選択理由

利用者にとって、ファイルピッカー、他アプリ、Termuxのどこから開いたかはタブ復元の期待を
変えない。探索テストでは、実ファイルのタブだけが復元され、Termux入力だけが消える経路差を
確認した。内部ファイル化すれば大きな本文を設定領域へ入れず、既存のサイズ検証・読込・復元を
再利用できる。ハッシュ化により元のローカルパスを内部ファイル名へ露出しない。

## 選択しなかった理由

プロセス内だけの保持は、Back後の再生成や再起動で作業状態を失う。SharedPreferencesは最大
10MBの本文を保存する用途ではなく、起動時のメモリ負荷も増える。明示的な保存要求は閲覧を
目的とする利用者へ不要な操作を課し、実ファイルから開いた場合との一貫性も失う。

## 決定を見直す契機

Androidが外部アプリから受信した一時文書の標準的な永続化機構を提供したとき、内部保存量の
上限や自動削除要件が必要になったとき、またはタブ復元が文書内容のスナップショットではなく
入力元との同期を要求するようになったときに見直す。
