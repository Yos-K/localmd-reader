# ADR-0021: クラウド実機でPro版の助言的探索を行う

状態: 採用

## 決定事項

Pro版のUI探索を、手動起動するFirebase Test LabのRoboテストとして1台のAndroid実機で行う。
Gradleで未署名の`ProPreviewDebug`をビルドし、GitHub ActionsからWorkload Identity Federationで
認証する。Test Lab専用サービスアカウントと結果バケットを使用する。

実機探索は必須マージゲートではなく助言的検査とする。実行時間は5分、10分、15分のいずれかに制限する。
完全な結果はTest Labに置き、エージェント確認用のmatrix情報、ログ、最大12枚のスクリーンショットだけを
GitHub Actionsに1日保存する。専用Cloud Storageバケットのオブジェクトは7日後に削除する。

## 検討した選択肢

- TermuxからワイヤレスADBで所有者のスマートフォンを操作する。
- GitHub Actionsのヘッドレスエミュレータだけを使い続ける。
- すべてのPull Requestで実機マトリクスを実行する。
- 署名済みPlayビルドをアップロードし、リリース前レポートだけに依存する。
- 専用クラウドIDを使い、手動起動の実機Roboテストを行う。

## 選択理由

クラウド実機なら所有者の画面を占有せず、既存エミュレータと異なり得る実ハードウェア、ベンダーWebView、
システムUI、Android動作を確認できる。Robo探索は重複したUIテスト一式を必要とせず、同じ端末構成なら
反復可能で、ログ、スクリーンショット、動画をエージェントが分析できる。手動起動、1台、時間上限により、
遅く不安定で課金対象となるlargeテスト層を価値に見合う範囲に保つ。

Pro preview variantは署名情報やPlay購入なしでProの振る舞いを有効にする。鍵を持たない専用IDにより、
ADR-0014の公開／非公開リリース境界を維持し、侵害時の影響を限定する。

## 選択しなかった理由

ワイヤレスADBは所有者の画面を占有し、未接続時には使えない。エミュレータだけでは実機の確信を得られない。
全PRで課金対象の実機テストを行うのは遅く不安定で、テストピラミッドに反する。Playのリリース前レポートは、
制御可能なPro previewの入口と同等ではなく、アップロード済みリリースに依存する。

## 決定を見直す契機

3回連続のリリース周期で実機固有の発見がない、Test Labの価格や提供状況が大きく変わる、Roboが重要な
WebViewまたはジェスチャー経路へ到達できない、あるいは安定した計装テストで許容コストのまま強いassertへ
置き換えられる場合に見直す。
